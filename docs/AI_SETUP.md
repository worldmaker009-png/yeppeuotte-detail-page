# AI 연결 및 배포 안내

## 현재 제공하는 것과 추가로 필요한 것

프런트엔드는 GitHub Pages를 그대로 사용합니다. AI는 별도 Cloudflare Worker에서 OpenAI의 이미지 입력 지원 모델을 호출합니다. 텍스트 기본 모델은 `gpt-4.1-mini`, 이미지 기본 모델은 `gpt-image-1.5`입니다. 계정이 해당 모델·이미지 편집·구조화 출력을 지원해야 하며, 이미지 모델은 추가 조직 인증이 필요할 수 있습니다.

추가로 필요한 서비스:

| 서비스 | 용도 | 비용·계정 |
| --- | --- | --- |
| GitHub Pages / Actions | 프런트엔드 배포 | 공개 저장소는 무료 이용 가능, Actions 한도 확인 |
| Cloudflare Workers + SQLite Durable Objects | API 키 보관, AI 중계, 영속 요청 제한 | 무료 요금제 제공 범위 내 사용 가능. 요청·CPU·저장소 한도 및 계정의 Durable Objects 사용 가능 여부 확인 |
| OpenAI API | 사진 분석, 한국어 문구 및 실사 가상 모델 컷 생성 | 사용량 기반 유료. ChatGPT 구독과 별도 결제이며 무료 이용은 보장되지 않음 |

사진 수·해상도·모델·응답 길이·생성 품질에 따라 AI 입력/출력 토큰 사용량이 달라 고정 건당 요금은 보장할 수 없습니다. 기본값은 **텍스트 3회/분·30회/UTC 일, 이미지 6컷/분·12컷/UTC 일**이며 모든 관리자의 합계입니다. 실패한 공급자 호출과 재생성도 횟수에 포함됩니다. 이미지 4컷짜리 상품은 이미지 일일 한도 12컷 기준 최대 3개이며 실패/추가 재생성 시 줄어듭니다. 일일 요청 제한은 금액 한도와 다릅니다. 처음에는 `DAILY_GENERATION_LIMIT`와 `IMAGE_DAILY_LIMIT`를 낮추고 OpenAI 프로젝트의 사용 알림·지원되는 제한을 별도로 설정하세요. 예산 알림만으로 강제 결제 차단이 된다고 가정하지 마세요.

Cloudflare 무료 CPU 한도에서는 큰 사진 여러 장의 검증·중계가 제한에 걸릴 수 있습니다. 로컬 테스트는 실서비스 무료 CPU 한도를 재현하지 않습니다. 실제 상품의 최대 사진 수로 테스트하고, CPU 초과가 발생하면 Workers Paid를 사용하세요(통상 월 US$5부터, 최신 공식 가격표 확인). 유료 플랜의 CPU 한도를 Cloudflare 설정에서 조정할 수 있습니다. 무료 호스팅만으로 모든 이미지 작업이 가능하다고 보장하지 않습니다.

## 설치 없이 계정 웹 화면에서 설정

### 예산 계산 예시와 실제 비용 확인

화면의 초깃값 **이미지 $0.25/컷 + 문구 $0.03/회**는 운영자가 변경할 수 있는 예산 가정입니다. 현재 공급자 가격을 조회한 값이나 확정 견적이 아닙니다.

| 구성 | 화면의 예산 가정 합계 |
| --- | --- |
| 1컷 + 문구 | $0.28 USD |
| 2컷 + 문구 | $0.53 USD |
| 4컷 + 문구 | $1.03 USD |

이미지 편집의 참조 입력(원본 3~10장 + 동일 인물 참조), high 품질 출력, 텍스트 분석 모두 실제 요금에 영향을 줍니다. 세금·환율·호스팅 초과분은 별도입니다. 공개 가격표를 확인해 **예상 비용 단가 설정**을 조정하세요. Worker의 `IMAGE_ESTIMATE_USD`, `TEXT_ESTIMATE_USD`로 기본 예산 가정을 설정할 수도 있습니다. 사용자가 단가를 수정한 경우 연결 확인이 그 값을 덮어쓰지 않습니다.

화면에는 해당 탭에서 시도한 요청 횟수·가정 단가 합계와 API가 반환한 이미지 생성 토큰 사용량도 표시합니다. 단가 가정을 바꾸면 화면 누적 예산도 새 가정으로 다시 계산됩니다. 실제 달러 청구액을 실시간 조회하는 기능은 아닙니다. 새로고침하면 화면 누적은 초기화되며, 서버의 일일 제한은 초기화되지 않습니다. OpenAI 프로젝트 Usage/Costs에서 실제 청구액과 실패/시간 초과 요청의 처리 여부를 확인하세요. 요청을 취소해도 이미 시작한 생성 비용이 취소된다고 보장할 수 없습니다.

### 1. Cloudflare 계정 및 배포 권한

1. Cloudflare 계정을 만들고 Workers & Pages에서 Workers 이용 및 workers.dev 하위 도메인을 준비합니다.
2. Cloudflare 프로필 → API Tokens에서 **Edit Cloudflare Workers** 템플릿을 사용해 대상 계정에만 배포할 수 있는 토큰을 만듭니다. 대상 계정의 Account ID도 확인합니다.
3. GitHub 저장소 **Settings → Secrets and variables → Actions → Secrets**에 아래 두 개를 등록합니다. 값은 채팅이나 코드에 적지 마세요.
   - `CLOUDFLARE_API_TOKEN`: 배포 토큰
   - `CLOUDFLARE_ACCOUNT_ID`: 대상 계정 ID
4. GitHub **Actions → Deploy AI backend to Cloudflare → Run workflow → main**을 실행합니다.
5. 실행이 성공하면 로그에 표시되는 Worker HTTPS 주소를 확인합니다. 예: `https://yeppeuotte-ai-api.<계정하위도메인>.workers.dev` (예시 주소이므로 그대로 사용하지 마세요).

워크플로는 코드와 요청 제한용 Durable Object를 배포합니다. OpenAI 키가 없어도 배포할 수 있지만, 키 설정 전에는 생성 API가 503 연결 필요 상태를 반환합니다. 배포 토큰은 Cloudflare에 런타임으로 전달하지 않으며, OpenAI 키는 이 워크플로에 넣을 필요가 없습니다.

### 2. API 키와 관리자 암호 등록

Cloudflare 대시보드 → 해당 Worker → Settings → Variables and Secrets에서 **Secret 유형**으로 등록합니다.

| 이름 | 값 |
| --- | --- |
| `OPENAI_API_KEY` | OpenAI 프로젝트의 API 키. 해당 프로젝트에 결제 및 모델 접근 권한 필요 |
| `ADMIN_TOKEN` | 비밀번호 관리자로 생성한 32~128자의 무작위 영문·숫자 접속 암호. OpenAI 키와 다른 값 사용 |

저장 후 Worker 배포/변경 적용을 완료합니다. 암호는 한 명 또는 소수의 신뢰하는 관리자용입니다. 화면에 입력한 접속 암호는 요청의 Authorization 헤더에만 사용하며 브라우저 저장소에 기록하지 않습니다. 비밀번호 관리자의 자동 저장 여부는 사용자가 관리하세요.

`backend/wrangler.toml`의 일반 환경 변수:

- `ALLOWED_ORIGIN`: `https://worldmaker009-png.github.io` — 끝의 슬래시와 저장소 경로 없음. 사용자 지정 프런트엔드 도메인을 쓰면 정확한 origin으로 수정합니다. `*`를 사용하지 마세요.
- `OPENAI_MODEL`: 기본 `gpt-4.1-mini`. 다른 모델 사용 시 이미지 입력·Responses API·JSON Schema 지원을 확인합니다.
- `DAILY_GENERATION_LIMIT`: 텍스트 기본 `30`, 분당 3회.
- `IMAGE_MODEL`: 기본 `gpt-image-1.5`. Images Edits, 여러 참조 입력, `input_fidelity=high`, `quality=high`, `size=1024x1536`, PNG 출력을 지원해야 합니다. 모델명을 바꾸는 것만으로 다른 공급자 API와 호환되지는 않습니다.
- `IMAGE_DAILY_LIMIT`: 이미지 기본 `12`, 분당 6컷. 일일 제한 설정은 1~1000 범위이며 UTC 날짜가 바뀌면 초기화됩니다.
- `IMAGE_ESTIMATE_USD`, `TEXT_ESTIMATE_USD`: 운영자가 수정하는 예산 가정. 기본 `0.25`, `0.03` USD. 실제 과금 단가를 자동 조회하지 않습니다.

Wrangler 설정의 일반 변수는 이후 코드 배포 시 다시 적용되므로 변경할 때 저장소 설정도 함께 수정하세요. Secret은 코드에 추가하지 않습니다.

### 3. 프런트엔드 연결

1. GitHub 저장소 **Settings → Secrets and variables → Actions → Variables**에서 `YEPPEUOTTE_AI_API_URL`을 추가합니다. 값에는 Worker의 HTTPS origin만 입력합니다. **이 변수는 공개 값이므로 API 키나 암호를 넣지 마세요.**
2. **Actions → Deploy studio to GitHub Pages → Run workflow → main**을 실행합니다. GitHub **Settings → Pages → Source**가 **GitHub Actions**인지 확인합니다.
3. 배포 성공 후 `https://worldmaker009-png.github.io/yeppeuotte-detail-page/`를 엽니다.
4. AI API 연결 설정을 펼쳐 관리자 접속 암호를 입력합니다. 공개 URL 변수를 사용하지 않은 경우 여기에 Worker URL을 직접 입력해도 됩니다.
5. **연결 설정 확인**을 누릅니다. '백엔드 설정 확인됨'은 키 등의 존재를 확인한 것이며, 유효한 키·잔액·모델 접근은 아직 검증하지 않은 상태입니다.
6. 상품 사진 3~10장을 추가하고 전송 동의 후 **AI 자동 생성**을 누릅니다. **실제 AI 생성 요청 성공**과 결과가 표시되어야 실제 연결이 검증됩니다. 오류가 나오면 성공한 것으로 간주하지 않습니다.
7. 상품명·소개·디자인 포인트·색상·스타일링을 검토합니다. 소재 성분, 사이즈·실측, 가격, 세탁 안내는 판매자가 확인해서 입력합니다. 기본적으로 사진만으로 채우지 않습니다.
8. 모델 사진을 원하면 **모델 사진 + 상세페이지 AI 제작**을 누릅니다. 아래 모델 제작 과정을 확인하세요.
9. PNG 저장으로 결과를 내려받습니다. 긴 페이지는 여러 파일을 순서대로 사용합니다.

누구나 열 수 있는 정적 화면과 비용이 발생하는 AI 요청을 분리했습니다. 공개 도구의 접근 자체를 제한하거나 사용자별 사용량·로그인 계정이 필요하면 별도 인증 시스템이 추가로 필요합니다.

## 마네킹에서 가상 모델·상세페이지까지

1. 같은 상품의 정면·측면·후면·단추 및 패턴 클로즈업 등 3~10장을 준비합니다. 서로 다른 상품을 한 번에 넣지 마세요. 원본과 모델 사진은 각각 별도로 유지됩니다.
2. 1·2·4컷, 배경(아이보리/화이트/그레이), 예상 단가를 선택합니다. 4컷은 정면 전신 → 측면 전신 → 3/4 전신 → 상반신 순서입니다.
3. **모델 사진 + 상세페이지 AI 제작**을 누르면 먼저 원본만으로 한국어 상품 정보를 분석합니다. 생성 사진에 나타난 새 디테일을 상품 사실로 사용하지 않습니다.
4. 백엔드는 마네킹 사진들을 참조한 Images Edits 요청으로 성인 가상 여성 모델의 정면 컷을 만듭니다. high 입력 충실도와 high 품질을 사용합니다.
5. 다음 구도들은 첫 생성 컷을 얼굴·체형 참조 이미지로 함께 보냅니다. 인물 기준은 사진을 개별 재생성/삭제해도 초기화 전까지 유지합니다. **생성 모델 사진 및 인물 기준 초기화**를 누르면 다음 생성에서 새 인물을 만듭니다.
6. 한 컷씩 완료되는 대로 갤러리와 세로형 페이지에 반영합니다. 이미지 4장을 한 번에 긴 서버 요청으로 만들지 않고, 컷별로 별도 요청하여 완료 결과를 보존합니다. 이미지당 대기 한도는 백엔드 150초/브라우저 180초이며 여러 컷은 수 분이 걸릴 수 있습니다.
7. **원본 비교**를 열어 원본 사진을 선택하며 단추 개수·패턴·색상·네크라인·길이·실루엣을 검사합니다. 각 컷의 **검수 완료**를 체크하고 상세페이지를 다시 만든 뒤 저장하세요. 생성 사진 중 미검수인 컷을 사용하면 페이지 다운로드가 비활성화됩니다. 제외한 컷은 검수 없이도 원본만 저장할 수 있습니다.
8. 각 컷은 **앞으로**, **재생성**, **PNG 저장**, **삭제**로 관리합니다. 개별 재생성은 추가 이미지 API 호출이며 문구를 다시 만들지 않습니다. 전체 제작 버튼은 문구와 선택한 구도를 다시 생성합니다. 배경을 바꾼 후 원하는 컷을 재생성할 수 있습니다. 정밀 부분 보정/브러시 편집은 포함하지 않습니다.
9. **AI 가상 모델 표시**가 기본 선택되어 상세페이지와 개별 PNG에 표시됩니다. 선택을 바꾸면 상세페이지를 다시 생성하세요. 이 설정은 사용자에게 생성 이미지를 명확하게 안내하기 위한 기능입니다.
10. **다음 생성 중단**은 진행 중 요청이 끝난 뒤 다음 컷을 시작하지 않습니다. 완료 컷은 보존합니다. 자동 재시도는 하지 않습니다.

동일 인물 참조와 의류 보존 프롬프트는 일관성을 유도하는 장치입니다. 실제 동일 얼굴·체형의 완전한 고정, 원본 의류의 픽셀 단위 복제, 정확한 길이·핏, 보이지 않는 부분의 정확성은 보장할 수 없습니다. 특히 측면/가려진 부위와 미세 패턴은 달라질 수 있습니다. 실사진 품질은 계정 연결 후 실제 상품으로 평가해야 하며, 불합격 컷은 제외하거나 다시 생성하세요. 원본 사진이 페이지 하단에 함께 제공되어 실제 상품 디테일을 확인할 수 있습니다.

## 데이터 흐름과 보안

`Chrome → (축소 JPEG + 관리자 암호/HTTPS) → Worker → (서버의 API 키/HTTPS) → OpenAI`

- 원본은 로컬에 보존합니다. 사진은 장당 15MB/4천만 화소 이하로 읽고, 분석용으로 긴 변 최대 1440px JPEG를 만듭니다. 1MB를 넘으면 1024px로 더 줄입니다. 원본 파일명과 EXIF 메타데이터를 AI 요청에 넣지 않습니다.
- AI 분석은 전송 동의 후에만 실행합니다. 수동 모드는 사진을 서버에 전송하지 않습니다.
- 백엔드는 3~10장, 장당 1MB 이하 JPEG 데이터와 전체 JSON 16MB 제한을 검사합니다. 임의 외부 이미지 URL을 받지 않습니다.
- CORS는 정확한 프런트엔드 origin만 허용합니다. CORS 자체는 인증이 아니므로 별도의 관리자 암호를 검증합니다. API 키와 관리자 암호는 분리합니다.
- 전역 요청 제한은 Durable Object 저장소 트랜잭션으로 관리합니다. 프로세스가 재시작되어도 한도가 유지됩니다. DB에는 텍스트/이미지별 일일·분당 카운터만 저장하고 사진·상품 정보는 저장하지 않습니다. 인증 실패는 OpenAI를 호출하지 않습니다.
- 백엔드는 응답 본문, 키, 사진을 로그에 기록하지 않습니다. 공급자 원문 오류도 프런트엔드로 전달하지 않습니다. Cloudflare의 플랫폼 요청 로그와 관측 설정은 계정 정책을 별도로 확인하세요.
- 모델 이미지용 `/model-image`는 3~10장의 원본 참조와 선택적인 인물 JPEG 참조만 받고, 허용된 구도·배경만 사용합니다. 임의 프롬프트나 외부 URL은 받지 않습니다.
- OpenAI Responses 요청에 `store: false`를 사용합니다. 이것이 모든 데이터 무보관을 보장하는 것은 아닙니다. 텍스트·이미지 공급자의 데이터 처리·모니터링 정책을 확인하고 사진 속 인물과 상품에 대한 적절한 이용 권한을 확보하세요.
- 프롬프트는 사진 속 지시를 따르지 않도록 구성하고 JSON Schema 및 응답 검사를 사용합니다. 비율·치수·세탁 관련 금지 표현을 추가 검사하지만 모든 환각을 자동 검출할 수는 없습니다. 사진상 조직감은 실제 섬유 성분을 증명하지 않으며 판매자 검토가 필요합니다.
- `.dev.vars`, `.env`, `.wrangler/`는 Git에서 제외됩니다. `public/`만 Pages에 업로드합니다. 공개 정적 파일에는 공급자 키를 절대 넣지 마세요.

## 문제 해결

| 표시 | 확인할 것 |
| --- | --- |
| AI API 연결 필요 | Worker 주소, API 키 Secret, 32자 이상의 관리자 암호, Durable Object 바인딩 |
| API 연결 실패 | Worker 배포 상태, HTTPS, CORS origin, 네트워크 차단 |
| 관리자 접속 암호 오류 | Cloudflare의 ADMIN_TOKEN과 화면 입력 일치 여부. OpenAI 키를 입력하지 않기 |
| AI API 키/모델 권한 | OpenAI 키 유효성, 프로젝트·모델 접근 권한 |
| AI 사용 한도/결제 | OpenAI 잔액, 결제 및 provider rate limit |
| 요청 한도 | Worker의 텍스트 3회/분·30회/일 및 이미지 6컷/분·12컷/일 기본 제한, UTC 날짜 |
| 확인되지 않은 주장 | 모델이 성분·치수·세탁 문구를 반환해 차단됨. 재생성 또는 수동 작성 |
| 이미지 API 접근 권한 | 이미지 모델 사용 권한, 조직 인증, API 키의 Images 권한 |
| 얼굴·의류가 달라짐 | 원본의 각도와 디테일 사진 보강, 인물 기준 유지, 재생성 후 비교·검수 |
| 시간 초과 | 공급자 응답 지연. 즉시 반복 재생성하지 말고 사용량도 확인 |
| PNG 저장 차단 | 브라우저의 여러 파일 다운로드 허용 또는 개별 링크 사용 |

## 검증 범위

구현 환경에서 다음 항목을 검증합니다.

- Node 단위/통합 테스트: 인증·CORS·크기 제한·3~10장·AI 응답 스키마·오류 전달·요청 횟수 저장·Images Edits multipart와 인물 참조·비용 예시 계산
- 실제 Cloudflare 로컬 런타임: 미설정 health 상태, 503 생성 차단, 잘못된 origin 차단
- Wrangler 배포 dry-run: 번들 생성과 Durable Object 바인딩
- Chromium 통합 테스트: 수동 입력, 명확한 미연결/오류, mock 텍스트/이미지 성공·4구도 인물 참조·재생성, 검수 전 저장 차단, AI 표시 PNG, 원본 비교, 판매자 확인 정보 보존, PNG의 실제 1720px 헤더, 모바일 화면, GitHub Pages 하위 경로

**Mock 테스트의 AI 응답은 테스트 코드에만 존재하며 배포 UI의 데모 모드로 사용하지 않습니다.** 구현 환경에는 OpenAI 키와 Cloudflare 배포 인증 정보가 없어, 유료 OpenAI 실사진 분석·실사 모델 이미지 품질 검증과 Cloudflare 공개 배포는 실행하지 못했습니다. 위 설정 후 실제 사진으로 성공을 확인해야 운영 준비가 완료됩니다. 코드의 GitHub 반영은 Pages/Worker 배포 성공을 의미하지 않습니다.
